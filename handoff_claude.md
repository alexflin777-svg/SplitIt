## Задача

Закрыть последний непроверенный слой — HTTP-обвязку Supabase. Локальный харнесс
покрывает политики базы на настоящем PostgreSQL, но PostgREST, GoTrue и триггер
на `auth.users` под живой сессией не работали ни разу.

Инструмент готов: `scripts/verify-production.mjs`. Ручной сценарий из семи
шагов в браузере он заменяет одной командой и, в отличие от него, убирает за
собой.

## Запуск

```bash
SUPABASE_SERVICE_ROLE_KEY=<ключ> npm run verify:prod
```

Ключ берётся из Supabase → Settings → API → `service_role`. **Передавайте его
строкой запуска, а не через `.env.local`:** он обходит RLS, и ему нечего делать
рядом с клиентской конфигурацией, которая вшивается в бандл.

Без ключа прогон тоже работает, но аккаунты останутся в проекте — скрипт
напечатает, что удалить руками.

Направить на отдельный проект-песочницу вместо боевого:

```bash
VERIFY_SUPABASE_URL=https://... VERIFY_SUPABASE_ANON_KEY=... npm run verify:prod
```

## Что проверяется

Девять шагов, 19 утверждений:

| Шаг | Что подтверждает |
|---|---|
| 1 | регистрация выдаёт рабочую сессию (GoTrue) |
| 2 | профиль создаётся триггером `on_auth_user_created` |
| 3 | `create_group_with_owner` атомарен, автор сразу владелец |
| 4 | посторонний не видит ни списка, ни расходов, ни кодов приглашений, ни группы по прямому id |
| 5 | прямая самозапись в чужую группу отклонена; вступление по коду работает; код одноразовый |
| 6 | после вступления видны событие, расход и профили участников — и только они |
| 7 | участник не переименовывает чужое событие и не записывает перевод от чужого имени |
| 8 | выход из группы возвращает данные в недоступное состояние |
| 9 | уборка: аккаунты удалены, каскад унёс событие |

Выход: `0` — всё прошло, `1` — есть провалы. Каждая строка печатается отдельно,
поэтому в отчёт можно вставить вывод целиком.

## Чего скрипт не покрывает

**Realtime.** Postgres Changes требуют WebSocket и второго живого клиента;
скрипт работает по HTTP. Проверяется по-прежнему вручную: два окна, A добавляет
расход, у B он появляется без перезагрузки.

**Интерфейс.** Скрипт бьёт по API напрямую и ничего не говорит о том, что видит
человек. Визуальный smoke остаётся отдельным шагом.

## Почему это не сделал я

Создание аккаунтов и ввод паролей — операции, которые я не выполняю, включая
приложение владельца. Поэтому инструмент написан, но ни разу не запущен: строки
вывода в этом файле — описание задуманного поведения, а не снятый результат.
Первый настоящий прогон будет и первой проверкой самого скрипта.

Если он упадёт на шаге 1 с упоминанием `confirm` — значит подтверждение email
снова включено; на 2026-08-01 `mailer_autoconfirm: true`, проверено запросом к
`/auth/v1/settings`.
