## S0-1. Миграция RLS открывает все финансовые таблицы

**Файл:** [supabase/migrations/20260731000000_init_splitit_schema.sql](supabase/migrations/20260731000000_init_splitit_schema.sql#L85)

На строках 101–105 созданы permissive-политики `FOR ALL USING (true)` для
`groups`, `group_members`, `expenses`, `expense_splits` и `settlements`.
В PostgreSQL permissive-политики объединяются через OR, поэтому ограничивающая
политика чтения группы на строках 96–99 становится бесполезной. Любой клиент с
табличными grants сможет читать, менять и удалять чужие финансовые данные.

Дополнительно:

- `profiles` разрешает публичный `SELECT USING (true)`;
- для записи нет `WITH CHECK`;
- `group_invites` вообще не включает RLS, хотя хранит коды приглашений;
- `exchange_rates` также не включает RLS.

**Ожидалось:** доступ только владельцу или участнику группы, запись проверяет
`auth.uid()`.

**Фактически:** SQL явно разрешает все действия без проверки пользователя.

**Доказательство:** строки 93–105 миграции. Живой прогон невозможен, потому что
миграция ещё не применена и настоящий Supabase не подключён. Именно поэтому
миграцию нельзя применять в production в текущем виде.

**Направление починки:** deny-by-default, отдельные политики SELECT/INSERT/UPDATE/
DELETE с `USING` и `WITH CHECK`, тест двумя реальными аккаунтами.

**Исполнитель:** ① Claude Code → ② CODEX review → ③ Checker с живым Supabase.

## S1-1. Пригласительная ссылка теряет группу и создаёт фиктивную

**Файлы:** [src/app/events/detail/EventDetailClient.tsx](src/app/events/detail/EventDetailClient.tsx#L56),
[src/lib/routes.ts](src/lib/routes.ts#L56),
[e2e/events.spec.ts](e2e/events.spec.ts#L87)

Если `groupId` отсутствует в localStorage нового браузера, `loadGroup()` не
показывает ошибку и не загружает группу с сервера. Вместо этого создаёт
«Совместную поездку» с Максимом и сохраняет её под тем же id. Параметр
`join=true` нигде не читается.

**Воспроизведение:**

1. Контекст A создал «Секретная поездка владельца».
2. Чистый контекст B открыл
   `/events/detail?id=group-1785524238441&join=true`.
3. B увидел «Совместная поездка», двух фиктивных участников и 0 ₽.

**Ожидалось:** та же группа, участники и транзакции владельца после явного
принятия приглашения.

**Фактически:** локальная подмена данных; ссылка передаёт только id.

**Доказательство:** [скриншот контекста B](output/playwright/invite-data-loss.png).
Существующий тест проверяет только HTTP 200, поэтому ложно зелёный.

**Исполнитель:** ① Claude Code (invite token + серверная загрузка) → ② CODEX →
③ Checker двумя контекстами.

## S1-2. «OTA-обновление» не обновляет приложение, но сообщает успех

**Файлы:** [src/lib/app-updater.ts](src/lib/app-updater.ts#L26),
[src/app/profile/page.tsx](src/app/profile/page.tsx#L119)

`checkForAppUpdates()` всегда возвращает зашитую `v2.4.0-OTA`.
`applyInAppOTAUpdate()` ждёт на таймерах, записывает версию в localStorage и
возвращает `true`. Новый bundle, manifest, checksum или native update не
загружается.

**Воспроизведение:** Профиль → «Проверить обновления» → «Обновить прямо сейчас».
UI меняет v2.3.0 на v2.4.0-OTA и пишет «Приложение успешно обновлено».

**Ожидалось:** подтверждённая установка нового артефакта либо честная пометка
демо/недоступно.

**Фактически:** меняется только
`localStorage['splitit_installed_app_version']`.

**Доказательство:** [ложный экран успеха](output/playwright/fake-ota-success.png).

**Исполнитель:** ① Claude Code (реальный update contract или удаление симуляции)
→ ④ Gemini (честное состояние UI).

## S2-1. Расходы и погашения принимают отрицательные суммы

**Файлы:** [NewExpenseClient.tsx](src/app/events/expense/new/NewExpenseClient.tsx#L101),
[EditExpenseClient.tsx](src/app/events/expense/edit/EditExpenseClient.tsx#L80),
[SettleUpClient.tsx](src/app/events/settle/SettleUpClient.tsx#L56)

Проверка `if (!parsedAmount)` блокирует ноль, но отрицательное число truthy.
У number inputs нет `min`; доменная проверка отсутствует.

**Воспроизведение:** создать расход `-1000` ₽. Он сохраняется, итог события
становится `-1 000 ₽`, а split получает `amountOwed: -1000`.

**Ожидалось:** ошибка валидации без изменения данных.

**Фактически:** отрицательная финансовая транзакция записана в localStorage.

**Доказательство:** [скриншот отрицательного итога](output/playwright/negative-expense.png).

**Исполнитель:** ① Claude Code → ② CODEX; регрессия для create/edit/settle.

## S2-2. Fallback-курсы валют используются молча

**Файл:** [src/lib/currency.ts](src/lib/currency.ts#L13)

Начальные курсы зашиты в код. Модуль ведёт `source: 'fallback'` и
`lastUpdated`, но `getExchangeRateStatus()` не вызывается ни в одном UI-файле.
На создании расхода live rates вообще не загружаются; на редактировании запрос
асинхронный, а пересчёт не подписан на его завершение.

**Ожидалось:** видимый источник/дата курса и явное предупреждение о fallback.

**Фактически:** пользователь получает финансовый пересчёт без информации о
качестве курса.

**Исполнитель:** ① Claude Code (rate state) → ④ Gemini (маркер в UI).

## S2-3. Playwright gate может пройти на чужом или устаревшем сервере

**Файл:** [playwright.config.ts](playwright.config.ts#L31)

Конфиг использует фиксированный порт 4173, `reuseExistingServer: !CI` и внутри
`webServer.command` повторно запускает build. При двух параллельных Checker:

1. оба начинают сборку;
2. первый занимает 4173;
3. второй получает `EADDRINUSE`;
4. его тесты всё равно проходят на сервере первого запуска.

В текущем прогоне наблюдалось `EADDRINUSE :::4173` и затем `28 passed`.

**Ожидалось:** один заранее собранный артефакт, уникальный/проверенный порт,
падение при постороннем сервере.

**Фактически:** зелёный статус не доказывает, какой именно `out/` тестировался.

**Исполнитель:** ② CODEX (test infrastructure).

## MCP: что подключено и что ещё требует владельца

В [глобальном конфиге Antigravity](/Users/annafa/.gemini/config/mcp_config.json)
ровно 12 серверов:

`StitchMCP`, `alloydb-postgresql`, `antimetal`, `chrome-control`,
`chrome-devtools-mcp`, `cloudrun`, `gitlab-orbit`,
`google-developer-knowledge`, `playwright`, `sequential-thinking`,
`supabase`, `testsprite`.

Подтверждено:

- Stitch: initialize 200, tools/list 200, 15 tools, битых локальных `$ref` нет;
- Google Developer Knowledge: initialize 200, 3 tools;
- Chrome Control (slim), Chrome DevTools, Cloud Run, Playwright, Sequential
  Thinking и TestSprite: stdio initialize успешен;
- JSON валиден, версии локальных npm-пакетов зафиксированы.

Требуется интерактивная/внешняя настройка:

- `antimetal`, `supabase`, `gitlab-orbit`: OAuth;
- `alloydb-postgresql`: без project/region/cluster/instance/database процесс
  ожидаемо завершается до initialize;
- `cloudrun`: сервер запускается, но вызовы требуют Google Cloud ADC/project;
- Chrome: разрешить remote debugging и обновить MCP в Antigravity.

API-ключи намеренно не приведены в отчёте.
