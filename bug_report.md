## Закрытые дефекты этого круга

### S1-1 — публичный Realtime Broadcast передавал пользовательский local store

**Файл:** `src/lib/supabase.ts`
**До исправления:** клиент подписывался на непублично защищённый канал
`splitit:user:<uuid>` без `private: true` и RLS, а в событие
`SPLITIT_DEVICE_SYNC` помещал целиком локальные `groups` и `friends`. Проверка
`user_id` только на приёмнике не является авторизацией: произвольный клиент мог
подписаться на известный topic и прочитать payload до этой проверки.
**Исправлено:** Supabase Broadcast этого типа удалён. Browser
`BroadcastChannel` передаёт только сигнал перечитать localStorage без
пользовательских данных. Межустройственная синхронизация групп остаётся в
`remote-store.ts` через PostgreSQL Changes и RLS.
**Доказательство:** в продуктовых файлах отсутствуют `SPLITIT_DEVICE_SYNC` и
вызов `.channel()` для локального store; `npm test` — 78/78.

### S2-1 — экран друзей фабриковал контакты и несуществующую возможность

**Файлы:** `src/lib/supabase.ts`, `src/app/friends/page.tsx`
**До исправления:** пустому пользователю автоматически добавлялись Максим,
Елена и Анастасия; контакт без телефона получал выдуманный номер и email
`@splitit.app`; статус показывался как «Активен»; «рабочая ссылка» вела на
`/auth?invite=friend`, хотя такой сценарий никого не добавлял.
**Исправлено:** пустой список действительно пуст; точные legacy demo-записи
мигрируются прочь без удаления реальных контактов; отсутствующие phone/email не
подменяются; статус честно называется «Локальный контакт»; неработающая ссылка
удалена и заменена объяснением, где создаётся настоящее приглашение в событие.
**Доказательство:** три новых сценария в `e2e/integrity.spec.ts` проходят на
mobile и desktop; после добавления контакта без телефона JSON не содержит полей
`phone` и `email`.

   URL для `https://split-it-ere9.vercel.app`.
3. Определиться с обязательным подтверждением email и SMTP для закрытой беты.
4. После push этой ветки дождаться Vercel preview/production deployment и

   опубликованному коммиту.

## Правила проекта

В `.agents/rules/antigravity2_core.md` устранено противоречие: обязательный
чек-лист теперь требует `npm test` с `pretest`, а не прямой
`npx playwright test`. Инвариант И-5 уточняет, что общий browser
BroadcastChannel допустим только без пользовательского payload.

## Решение по ветке и релизу

Ветка является кандидатом на передачу следующей роли: гейт зелёный, S0/S1 на
проверенном срезе нет. Публичная beta-ready отметка остаётся закрытой до
двухаккаунтного production-flow и проверки Auth URL/SMTP. Открытый S3-2 не
ломает данные, но должен быть исправлен Gemini до широкой раздачи.
