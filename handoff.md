## 1. Цель проекта

**SplitIT (Сплит-Чек)** — приложение для разделения совместных расходов в
группах: поездки, аренда жилья, рестораны, вечеринки. Пользователь заводит
событие, добавляет участников и расходы, а приложение считает, кто кому сколько
должен, и сводит долги к минимальному числу переводов.

Из `PRD.md`:

- Next.js 14 (App Router, TypeScript, Tailwind) + Supabase (PostgreSQL, Auth,
  Realtime).
- Мультивалютность: RUB, USD, EUR, KZT, GEL, AED, TRY.
- Алгоритм упрощения долгов — минимальное число платежей в графе должников.
- OCR чеков через Tesseract.
- Offline-first: локальная запись мгновенно, синхронизация поверх.
- Дистрибуция: статический экспорт → Capacitor → APK и IPA, плюс веб-версия.
  По `LAUNCH_ROADMAP.md` первый этап — закрытая бета на 15–30 тестировщиков.

**Ограничение, определяющее почти все решения:** `output: 'export'`. Серверного
рантайма нет ни в APK, ни на статик-хостинге — значит нет API routes, нет SSR и
нет динамических маршрутов, которые не были собраны заранее. Идентификаторы
живут в query-строке, а не в пути.

## 2. Текущее состояние

### Проверки

```

npm run lint          0, ноль предупреждений
npm run test:rls      25 passed на настоящем PostgreSQL
```

`npm test` собирает `out/` скриптом `build:test` с пустыми ключами. **Прямой
запуск `npx playwright test` минует хук `pretest`** и гоняет тесты по чему
попало — так уже случилось один раз и дало 44 ложных падения.

### Что работает

- Регистрация, вход, демо-вход, выход. Вход по чужому паролю отклоняется.
- Создание события, открытие по своей ссылке, вложенные экраны.
- Упрощение долгов: 9000 ₽ на троих → ровно два перевода по 3000.
- Ссылка на чужое событие даёт экран «недоступно» и ничего не пишет в
  хранилище. Открытие события никого не дописывает в участники.
- Отрицательные и нулевые суммы отклоняются на трёх уровнях: разметка,
  обработчик, `CHECK` в базе.
- Видно, загружен курс валют или взят резервный.
- Экран обновлений не обещает установку, которой нет.
- Контраст текста проверяется тестом на пяти экранах.

### Три вещи, которые не закончены

**1. Миграции не применены — приложение сломано.** Это главное.

Проект Supabase создан, ключи в `.env.local` прописаны, GoTrue отвечает 200.
Но схемы нет: все семь таблиц дают `404 PGRST205: Could not find the table`.
Ключи есть → `isMultiUser()` возвращает `true` → приложение считает себя
сетевым и падает на каждом экране. Без ключей оно работало.

```bash
curl -s -o /dev/null -w "%{http_code}\n" \
  "$NEXT_PUBLIC_SUPABASE_URL/rest/v1/groups?select=id&limit=1" \
  -H "apikey: $NEXT_PUBLIC_SUPABASE_ANON_KEY"
```

`200` — схема на месте, `404` — нет. Лечится выполнением трёх файлов из
`supabase/migrations/` в SQL Editor по порядку.

**2. Пуш на GitHub не прошёл.** Коммиты сделаны локально, remote подключён по
SSH (`git@github.com:alexflin777-svg/SplitIt.git`, ключ привязан к аккаунту,
проверено). Веток на remote нет.

Причина не в правах, а в объёме: 590 МБ и ~20 000 объектов. `git rm --cached`
убрал `node_modules` из будущих коммитов, но блобы остались в старой истории и
уезжают целиком. Пуш упёрся в таймаут.

**3. `NEXT_PUBLIC_APP_URL` всё ещё `http://localhost:3000`.** Он попадает в
ссылки-приглашения и должен совпадать с Site URL в настройках Supabase Auth.

## 4. Что пробовал — без результата

Раздел про тупики и потерянное время, чтобы следующая роль не повторяла.

### `git reset --hard` уничтожил работу

Первый коммит получился нечестным: сообщение описывало чистку индекса, а внутри
лежала вся работа пяти кругов. Пытаясь переделать, выполнил
`git reset -q --hard HEAD` — и откатил все правки в отслеживаемых файлах.
`ocr.ts`, `app-updater.ts`, `currency.ts`, `layout.tsx`, `progress.md` и
init-миграция вернулись к состоянию до аудита, вместе с политиками
`FOR ALL USING (true)`.

Спасло то, что коммит уже существовал: `git reset --hard d0ac5a5f` из reflog
вернул всё. Но `.env.local` к тому моменту был убран из индекса, поэтому его
перезаписала старая отслеживаемая версия с плейсхолдерами — ключи Supabase
пришлось вписывать заново вручную.

Правильный ход был `git reset --soft` с самого начала: он двигает HEAD, не
трогая ни индекс, ни рабочее дерево. Дальше по тексту я так и делал.

### Тесты зависели от `.env.local` разработчика

После появления настоящих ключей девять E2E-проверок посыпались: приложение
ушло в сетевой режим, а набор написан под локальный. Прогон зависел от того,
что лежит в файле у конкретного человека.

Починено скриптом `build:test` с пустыми ключами плюс `e2e/build-mode.spec.ts`,
который падает первым и объясняет причину. Проверено обратно: на сборке с
настоящими ключами сторож падает с внятным сообщением.

### `npx playwright test` вместо `npm test`

Дало 44 падения на пустом месте: `npx` минует хук `pretest`, а значит `out/`
не собирается вовсе. Выглядело как развал всего набора.

### Массовая замена ссылок регулярками

Скрипт вставки импортов искал «последнюю строку, начинающуюся с `import`», и в
четырёх файлах воткнул импорт **внутрь** многострочного блока — сборка
развалилась на `TS1003`. Отдельно: подстановка `router.push` по общему шаблону
увела на форму создания вместо созданного события. Поймал глазами, не тестом.

### Первая версия харнесса RLS ничего не проверяла

Использовал `SET LOCAL ROLE` вне транзакции. Конструкция там не действует,
запросы молча шли под владельцем схемы, а владелец обходит RLS. Харнесс зеленел
бы на полностью открытой базе. Теперь роль и `auth.uid()` сверяются перед
каждым блоком, несовпадение — ошибка.

### Первая версия теста на контраст

Сравнивала цвет текста с фоном карточки, а не ближайшего окрашенного предка:
аватар-эмодзи на синем градиенте засчитался как «белое на белом». Плюс эмодзи
вообще не подчиняются CSS `color`.

### Ручное вождение браузера для проверки форм

Кликал по координатам со скриншота: он отдаётся в удвоенном разрешении, а клики
принимаются в CSS-пикселях. Клик на `y=1084` при высоте 812 уходил за экран,
форма не отправлялась, и это выглядело как дефект приложения. Шесть ходов
впустую. Playwright попал с первого раза.

### Селекторы по памяти вместо чтения разметки

`getByPlaceholder(/Поездка|Название/i)` при реальном «Например: Алтай 2026»;
`paidBy` вместо `paidById`; проверка названия группы на экране, который его не
показывает. Пять падений подряд, ни одно не было дефектом приложения.

### MCP и окружение

`supabase`, `antimetal`, `gitlab-orbit` требуют OAuth. `alloydb-postgresql`
завершается до initialize без project/region/cluster. `gh`, Docker, Postgres и
`brew` на машине отсутствуют — отсюда PGlite вместо `supabase start` и
невозможность создать репозиторий из CLI.
