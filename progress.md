### [2026-08-01] Этап 9: граница Realtime и честные локальные контакты (CODEX/Чекер)

Полный обязательный прогон: `lint` exit 0, `tsc` exit 0, **`test:rls` 28/28**,
production build 15 страниц, **`npm test` 78/78** на mobile и desktop. Живой
smoke по свежему `out/` на 375×812 и 1280×720 — без console errors; доказательства
в `output/playwright/round7-friends-*.png`.

**Закрыта утечка через старый Realtime Broadcast.** Клиент больше не рассылает
локальные группы и контакты в topic, построенный из UUID. Browser
`BroadcastChannel` несёт только сигнал перечитать localStorage; межустройственные
группы синхронизируются через PostgreSQL Changes и RLS.

**Убраны выдуманные контакты и возможности.** Пустой список друзей остаётся
пустым, точные записи старого демо-набора мигрируются прочь, контакт без телефона
не получает выдуманные phone/email. Неработающая «рабочая ссылка» удалена;
экран честно объясняет, что локальный контакт не равен участнику события.

Live Supabase повторно проверен: все пять миграций на месте, Security Advisor
`lints: []`. В Auth всё ещё 0 пользователей, поэтому production-flow двумя
аккаунтами остаётся блокером беты. Единственный открытый продуктовый дефект в

**Закрыта дыра в покрытии, державшаяся три круга.** Политики RLS проверялись
разбором SQL текстом — это ловило форму дефекта, но не отвечало, увидит ли один
пользователь финансы другого. Теперь отвечает сам PostgreSQL: миграции
накатываются на PGlite (тот же движок в WebAssembly), запросы идут от лица трёх
пользователей под ролью `authenticated`. Docker и локальный Postgres на машине
недоступны — проверка всё равно есть.

**Приложение переведено на общее хранилище.** Появились `remote-store.ts`
(Supabase) и `store.ts` (фасад, выбирающий сетевой или локальный режим). Все
девять экранов работают через фасад и про режим не знают. Попутно убраны три
подстановки выдуманных данных: экран баланса рисовал «Участник 2», экран
расчёта — «Совместную поездку» с Максимом, форма расхода — двух вымышленных
людей.

**Приглашения переделаны.** Ссылка несёт одноразовый код со сроком жизни, а не
id группы, вступление живёт на отдельном экране и требует явного нажатия. По id
вступить нельзя: прямая запись в `group_members` разрешена только владельцу, а
коды не видны посторонним.

**Чего нет:** проекта Supabase. Его создание требует регистрации и входа через
браузер — это шаг владельца. Пока `.env.local` пуст, приложение работает
локально и говорит об этом на четырёх экранах. Инструкция:
[SUPABASE_SETUP.md](SUPABASE_SETUP.md).

### [2026-07-31] Этап 6: починка по отчёту круга 3

Прогон: `tsc --noEmit` чисто, `npm run lint` exit 0 без предупреждений,
`npm run build` 14/14 страниц, `playwright test` **58 passed** на `out/`.
Тестов стало вдвое больше: добавлены `e2e/rls.spec.ts` и `e2e/integrity.spec.ts`.

**Релиз разблокирован по S0.** Permissive-политики `FOR ALL USING (true)` сняты,
RLS переписан по принципу deny-by-default: отдельная политика на операцию с
`USING` и `WITH CHECK`, членство через `SECURITY DEFINER` функции, вступление в
группу только через `redeem_group_invite()`, `CHECK`-ограничения на суммы.
Вторая миграция закрывает базы, куда успела примениться первая редакция.

**Приложение перестало обещать несуществующее.** Ссылка на чужое событие даёт
экран «Событие недоступно» вместо выдуманной группы, и ничего не пишет в
хранилище. Добавление в участники — только по явному нажатию. Симуляция
OTA-обновления удалена целиком вместе с подписью «2.4-OTA» в шапке. Сбой
распознавания чека больше не выглядит как продолжающееся сканирование.

**Деньги под тройной защитой.** Отрицательные и нулевые суммы отклоняются
разметкой, обработчиком и `CHECK` в БД. Под сконвертированной суммой видно,
загружен курс или резервный.

**Проверки стали настоящими gate.** `npm run lint` не открывает мастер и падает
на предупреждениях; Playwright не переиспользует чужой сервер и сверяет
`BUILD_ID` сборки. Шрифт Inter уехал с CDN в сборку — в APK без сети он раньше
не загружался.

Открытым остаётся S3-2 (десктопная вёрстка `/auth`, зона Gemini) и живая
проверка RLS двумя аккаунтами: её нельзя выполнить, пока нет проекта Supabase.
Подробности: [bug_report.md](bug_report.md).

### [2026-07-31] Этап 5: независимая проверка CODEX/Чекера

Повторно пройдены `tsc --noEmit`, production build и 28 Playwright-тестов на
`out/`. Дополнительный живой прогон двумя изолированными контекстами нашёл
дефекты вне текущего покрытия.

**Релиз заблокирован:** миграция Supabase содержит permissive RLS-политики
`FOR ALL USING (true)`. Применять её к production нельзя. Пригласительная ссылка
не загружает существующую группу, а создаёт локальную демо-группу с тем же id.
«OTA-обновление» симулируется таймером и записью версии в localStorage.

Также подтверждены отрицательные расходы, игнорирование `?mode=login`, скрытый
fallback валют, интерактивный lint и гонка Playwright на порту 4173. Полный
разбор и доказательства: [bug_report.md](bug_report.md).

### [2026-07-31] Этап 4: Аудит, починка блокеров, тестовая обвязка

Проверено на статическом экспорте `out/`, а не в `next dev`. Прогон:
`tsc --noEmit` чисто, `npm run build` 14/14 страниц, `playwright test` 28 passed.

**Закрыто:**
- Вход больше не пускает по произвольному паролю. Раньше `signInUser` вообще
  не смотрел на аргумент `password`: любой email с любым паролем создавал
  сессию, а знакомый email отдавал чужой профиль целиком.
- Созданное пользователем событие открывается. Раньше `group-<timestamp>`
  упирался в три зашитых `generateStaticParams` и отдавал `404.html` в APK,
  IPA и на статик-хостинге.
- Отсутствие бэкенда стало видимым: баннер на экране авторизации вместо тихой
  подмены локальным режимом. Плейсхолдеры больше не вшиваются в сборку.
- Realtime-канал скоуплен на пользователя, входящий payload проверяется,
  состояние сливается вместо перезаписи, подписка снимается.
- Сброс пароля перестал рапортовать об успехе, когда письмо уйти не может.
- Аватар проверяется и сжимается до 256×256 перед записью в localStorage.
- Белый текст на белых карточках на шести экранах — вернулись тёмные градиенты.

**Поднято:** Playwright с 28 регрессиями (`e2e/`), статический сервер
`scripts/serve-out.mjs`, `npm test`. Эти регрессии не покрывают новые блокеры
этапа 5 и не являются достаточным release gate.

**Не работает и честно об этом сообщает:** синхронизация между устройствами и
восстановление пароля по email. Требуют настоящего проекта Supabase — `.env.local`
пуст. Схема из `supabase/migrations/` никуда не применена.
