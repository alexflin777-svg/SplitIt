# SplitIT: UX, Auth & Bug Fix Proposal

В соответствии с вашим запросом, я провёл дизайн-ревью и анализ кода (без внесения изменений). Ниже представлены корневые причины багов и предложения по их решению.

## 1. Баг: Друзья не добавляются из списка в группу
**Корневая причина:** 
В компоненте `EventDetailClient.tsx` (и `EventNewClient`) функция `addMemberByName(nameStr)` добавляет нового участника в локальное состояние группы. Однако, когда пользователь кликает по чипсу друга в модалке (внутри `setShowPhonebookModal`), функция вызывается корректно, модалка закрывается, но визуальное отображение `group.members` на экране не обновляется мгновенно из-за того, что функция не дожидается коммита в Supabase/локальный store, либо не вызывает форсированный ре-рендер списка участников перед закрытием модалки.
**Решение (Proposal):**
Изменить `addMemberByName` так, чтобы она гарантированно дожидалась `await setGroup(...)` и только после этого закрывала модалку, либо обновлять optimistic state массива `group.members` до записи в БД.

## 2. Баг: Не работает проверка обновлений по кнопке
**Корневая причина:** 
В `src/lib/app-updater.ts` функция `checkForAppUpdates()` запрашивает манифест обновления по URL из переменной окружения `NEXT_PUBLIC_UPDATE_MANIFEST_URL`. Если эта переменная не задана в `.env.local` или на Vercel, функция просто возвращает статус `unconfigured` со словарным ключом (текстом), но UI в `profile/page.tsx` никак не привлекает внимание пользователя к этому состоянию (сообщение рендерится как бледный текст).
**Решение (Proposal):**
Сделать визуальный feedback: если `status === 'unconfigured'`, выводить toast-уведомление (toast/alert) с текстом: «Канал обновлений не настроен», чтобы кнопка не казалась «мертвой».

## 3. Фича: Съезжающие поля (Mobile View)
**Корневая причина:** 
На узких экранах (iPhone SE и т.д.) некоторые Flex-контейнеры (например, карточки баланса и инпуты в создании события) не имеют `flex-wrap` или `min-w-0`, из-за чего длинные имена или суммы выталкивают кнопки за пределы экрана (`overflow`). В частности, проблемы замечены в `bottom-nav-overlap`.
**Решение (Proposal):**
Провести аудит компонентов в `src/app/events` и добавить классы `truncate`, `min-w-0` (для flex-детей) и `flex-wrap` для контейнеров со сложной версткой. Убедиться, что `padding-bottom` страниц учитывает высоту `BottomNav` во всех состояниях.

## 4. Фича: Импорт контактов из телефонной книги
**Решение (Proposal):**
Так как мы собираем приложение через Capacitor, мы можем использовать нативный плагин `@capacitor-community/contacts`.
1. Добавить плагин в `package.json` и настроить Permissions в `AndroidManifest.xml` / `Info.plist`.
2. На экране `/friends` и в модалках добавления в событие добавить кнопку «Импорт из контактов».
3. При нажатии — запрашивать разрешение, открывать нативный пикер, забирать Имя и Телефон, и сохранять в локальный стор (Supabase).
*Ограничение Web/PWA:* В чистом вебе (без Capacitor) Contacts API работает крайне ограниченно (по соображениям приватности браузеров). Для PWA эту кнопку нужно будет скрывать или показывать fallback-сообщение «Доступно только в приложении».

## 5. Фича: Новые соц. логины (Google, Telegram, WhatsApp)
**Решение (Proposal):**
Сейчас в проекте настроен локальный вход, демо-вход и заглушка для Telegram WebApp.
*   **Google OAuth:** Интеграция уже есть в коде (`signInWithGoogle()` в Supabase), но на странице `/auth` она скрыта или работает нестабильно. Нужно включить провайдера Google в настройках Supabase Dashboard, прописать Client ID/Secret от Google Cloud Console, и раскомментировать кнопку.
*   **Telegram Login:** У нас реализована логика для Telegram WebApp (`tg.initDataUnsafe`). Для обычного веба нужен Telegram Login Widget. Нужно создать бота через BotFather, привязать домен `splitit-apps.com`, и интегрировать Supabase Auth (Supabase поддерживает Telegram из коробки).
*   **WhatsApp Login:** Supabase Auth не поддерживает WhatsApp напрямую как OAuth-провайдера (так как у WhatsApp нет классического OAuth для логина). Альтернатива: авторизация через WhatsApp OTP (мы отправляем код в WhatsApp через Twilio/Meta API, пользователь вводит его на сайте). Это требует подключения платных сервисов.
